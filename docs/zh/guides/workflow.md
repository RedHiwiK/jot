Jot 有五种状态。每种状态记录的是你的意图，而不是某个进程是否在运行。

| 状态 | 含义 | 是否显示在看板上 |
|---|---|---|
| `inbox`（收件箱） | 已录入，尚未开始 | 是 |
| `in_progress`（进行中） | 正在处理，包括评审和验收 | 是 |
| `on_hold`（暂缓） | 推迟，或在等待外部条件 | 是 |
| `done`（已完成） | 已完成 | 仅在侧栏显示 |
| `archived`（已归档） | 不会做了；仍可搜索和恢复 | 否 |

## 修改状态

```bash
jot mv 42 in_progress
jot mv 42 on_hold
jot mv 42 done
jot mv 42 inbox
```

在 App 中，把卡片拖到另一列即可。任何状态都可以直接转到其他任何状态；每次流转的时间和操作者都会记录在 state log 中。

## 归档与恢复

```bash
jot rm 42            # 归档
jot mv 42 inbox      # 恢复
```

归档会保留需求及其 Markdown 文件。已归档的需求不会出现在看板和默认列表里；可以用 `jot ls --all --state archived`、App 的搜索，或**设置 → 已归档**找到它们，后者也可以将其恢复。

## 永久删除

```bash
jot purge 42             # 会要求确认
jot purge 42 43 --yes
```

`purge` 只接受已归档的需求。它会删除数据库记录、标签、链接、状态历史和 Markdown 文件，且无法撤销，建议优先使用归档。

在 App 中，右键卡片或列表行，选择**删除…**。确认后，App 会先归档（如尚未归档）再永久删除。

## 典型的一周

1. 白天随手录入，所有内容都落到**收件箱**。
2. 每周整理一两次收件箱：[归类](./projects-and-tags.md#归类)项目、给发布版本打标签、归档不再重要的需求。
3. 开始做的需求移到**进行中**；被阻塞的放到**暂缓**，并在正文里写明在等什么。
4. 交付后标记为**已完成**；`jot ls --tag v1.2 --all` 可以看到整个版本的内容。

## 优先级

```bash
jot set 42 --priority 1      # 高
jot set 42 --priority 0      # 普通
```

`jot ls` 和 JSON 结果会在每个状态内把高优先级的需求排在前面。优先级不影响状态，App 也不显示优先级。
